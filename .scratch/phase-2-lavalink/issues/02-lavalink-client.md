## Context

lavalink.md §3: ใช้ REST เท่านั้น (ไม่ใช้ WS/session/player ของ Lavalink — ไม่มี Discord); timeout ~10 s + circuit breaker สำหรับ fail-soft. ตำแหน่ง: `apps/server/src/services/lavalink/LavalinkClient.ts` — "คนเดียวที่รู้จัก Lavalink"

## Work

1. `services/lavalink/types.ts` — type ตาม Lavalink v4 REST จริง (lavalink.md §6): `LavalinkTrack { encoded, info{identifier,isSeekable,author,length,isStream,position,title,uri?,artworkUrl?,isrc?,sourceName}, pluginInfo?, userData? }`, `LoadResult` discriminated union 5 loadTypes (track/search → data, playlist → { info, tracks }, empty → null, error → { message, severity, cause }), `LavalinkInfo` (/v4/info: version, sourceManagers, plugins)
2. `LavalinkClient` — constructor `{ baseUrl, password, timeoutMs=10_000, breakerThreshold=3, breakerCooldownMs=30_000, fetchImpl? }`
   - `loadTracks(identifier)` → GET `/v4/loadtracks?identifier=…` (encodeURIComponent)
   - `decodeTrack(encoded)` → GET `/v4/decodetrack?encodedTrack=…`
   - `getInfo()` → GET `/v4/info` (health check)
   - header `Authorization: <password>` (ไม่ใช่ Bearer — ตาม spec ของ Lavalink)
   - timeout ผ่าน `AbortSignal.timeout()`; fetch error/timeout/HTTP>=500 → LavalinkUnavailableError; 401/404 → LavalinkError(status) **ไม่นับ**เข้า breaker (config bug ตรวจได้จาก log ทันที); 5xx **นับ**
   - circuit breaker: consecutive failures ≥ threshold → open (reject ทันทีด้วย LavalinkUnavailableError); พ้น cooldown → ยอมให้ผ่าน 1 request (half-open), สำเร็จ → close, ล้มเหลว → open ใหม่
3. Unit tests กับ mock HTTP server (node:http, port 0 — hermetic, ไม่แตะ docker):
   - happy path + assert Authorization/path/query
   - 401 → LavalinkError ไม่ทริป breaker
   - 5xx × threshold → breaker open → request ถัดไปไม่ยิงออกนอก (นับ server hits)
   - พ้น cooldown → half-open; สำเร็จ → close
   - timeout → LavalinkUnavailableError
   - `getInfo()` happy
