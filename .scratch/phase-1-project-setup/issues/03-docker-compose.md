# 03 — docker-compose + Dockerfiles + resolver placeholder

Status: resolved
Category: enhancement

## Brief

`docker-compose.yml` ครบ 5 services ตาม roadmap:

- `postgres` — image postgres:16, healthcheck, volume สำหรับ data, env จาก `.env`
- `lavalink` — image `ghcr.io/lavalink-devs/lavalink:4` + `application.yml` แบบ minimal (mount ผ่าน volume) — Phase 1 แค่ให้ container ลุกได้; **การ verify config จริงเป็นงาน Phase 2 ตาม lavalink.md §2.2**
- `resolver` — placeholder service แยก container (stub Node http เล็ก ๆ ใน `services/resolver/`): ทุก endpoint ตอบ 503 JSON พร้อมข้อความ "resolver not implemented (Phase 3)" + `GET /health` ตอบ 200 — เพื่อให้ compose topology ครบและ server อ้าง `RESOLVER_URL` ได้ตั้งแต่ตอนนี้
- `server` — build จาก `apps/server` Dockerfile (multi-stage: pnpm build → runtime), รัน migration อัตโนมัติตอน boot ก่อน listen (ดู ticket 04), `depends_on: postgres (condition: service_healthy)`
- `web` — build จาก `apps/web` Dockerfile (build Vite → serve ด้วย nginx:alpine หรือเทียบเท่า)

ข้อกำหนด: ทุก secret/config มาจาก env ไม่ hardcode; เครือข่ายเดียวภายใน compose; แค่ expose port ที่จำเป็นออกนอก (web, server, postgres สำหรับ dev)

## DoD

- `docker compose up --build` จากไฟล์เดียว → web แสดงหน้า login placeholder, `GET /health` ของ server ตอบ 200, postgres healthy, lavalink + resolver container ลุก
