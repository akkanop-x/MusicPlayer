# 04 — Drizzle init + migration แรก

Status: resolved
Category: enhancement

## Brief

ตั้ง Drizzle ORM + Drizzle Kit ใน `apps/server` แล้ว generate migration แรกให้ครบ schema ตาม [database.md](../../../docs/database.md) §2 (ทุก table):

- `users`, `tracks`, `playlists`, `playlist_tracks`, `liked_tracks`, `listening_history`, `user_settings`, `eq_presets`, `queue_snapshots`, `queue_items`
- กฎจาก doc: UUID PK (`gen_random_uuid()`), `created_at TIMESTAMPTZ NOT NULL DEFAULT now()` ทุก table, UNIQUE ทุกที่ที่ doc ระบุ (เช่น `tracks(source_name, source_identifier)`, `playlists(user_id, name) WHERE is_deleted = false` — partial), GIN index บน `tracks.genres` และ pg_trgm บน `(title, artist)`, composite PK ของ `liked_tracks`
- `pg_trgm` extension ต้องถูก enable ใน migration
- Migration รันอัตโนมัติตอน server boot (drizzle-orm migrate) — ตาม DoD "migration run อัตโนมัติ"
- drizzle.config.ts + script แยก `db:generate` / `db:migrate` สำหรับ dev

## DoD

- `docker compose up` ครั้งแรก → ทุก table + index ถูกสร้างใน postgres โดยไม่ต้องสั่งมือ
- SQL ที่ generate ตรงกับ database.md (ตรวจด้วยการอ่าน migration file ก่อน commit)
