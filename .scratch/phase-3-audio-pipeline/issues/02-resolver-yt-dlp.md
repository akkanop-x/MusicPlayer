# 02 — Resolver service จริง (yt-dlp container)

Status: resolved

> _This was generated by AI during triage._

## Context

audio-pipeline.md §2/§3.1 + ADR-007/008: resolver = container แยก (yt-dlp), trackId/identifier → stream URL อายุสั้น; แยกเพื่อ isolate CPU/deps/crash + อัปเดตง่ายเมื่อ YouTube เปลี่ยนกลไก

## Work

1. `services/resolver/` เขียนทับ stub: Node (node:22-alpine) + python3 + pip + yt-dlp (pin เวอร์ชัน)
2. `GET /resolve?identifier=<videoId>&source=youtube`:
   - รัน `yt-dlp -f bestaudio[acodec^=opus]/bestaudio -g --print-json` (หรือ `-J`) เฉพาะ fields ที่ต้องการ
   - ตอบ `{ streamUrl, contentType, durationMs }` — contentType จาก format (audio/webm; codecs=opus หรือ audio/mp4)
   - error → shape กลาง: ไม่เจอ/อายุ RESTRICTED → `TRACK_UNPLAYABLE`; อื่น ๆ → `UPSTREAM_UNAVAILABLE`
   - timeout ต่อ extraction 15 s + จำกัด concurrent extractions (เช่น 2)
3. In-memory cache: key = source:identifier, TTL 60 s
4. `GET /health` คงเดิม + รายงาน yt-dlp version
5. Dockerfile: layer ติดตั้ง yt-dlp แยก (cache), USER node, ไม่ expose ออกนอก network จริง (compose ยัง map port ไว้ dev)

## Acceptance

- `docker compose up -d resolver` + curl `/resolve?identifier=dQw4w9WgXcQ&source=youtube` → ได้ streamUrl (googlevideo) จริง
- resolve ซ้ำใน 60 s → cache (ไม่เรียก yt-dlp ซ้ำ — ดูจาก log/timing)
