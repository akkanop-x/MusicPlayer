# 03 — SSRF guard + StreamService (proxy + prebuffer + Range/206)

## Context

security.md §8 (SSRF guards บังคับ) + audio-pipeline.md §3–5 + ADR-008 (in-memory proxy, ห้ามดึงทั้งเพลง)

## Work

1. `security/ssrf.ts`:
   - `assertSafeUrl(url)`: https และ host อยู่ใน allowlist (env `SSRF_HOST_ALLOWLIST` default `*.googlevideo.com`)
   - DNS resolve ทุก hostname → ตรวจทุก IP: บล็อก loopback/private(10/8,172.16/12,192.168/16)/link-local(169.254/16)/ULA(fc00::/7)/0.0.0.0/8/metadata(169.254.169.254)
   - ผูก connect กับ IP ที่ตรวจแล้ว (กัน DNS rebinding); fetch ด้วย dispatcher ที่ pin IP หรือ custom lookup
2. `ResolverClient` (services/): `resolve(source, identifier)` — timeout 15 s + circuit breaker แบบ LavalinkClient + error mapping จาก resolver
3. `StreamService.openStream(trackId, rangeHeader)`:
   - trackId → tracks row (cache streamUrl ต่อ trackId TTL 60 s; หมด → เรียก resolver ใหม่ + อัปเดต tracks.stream_url/content_type)
   - SSRF check URL ก่อนยิง; forward `Range` header ไป upstream
   - redirect ≤ 3 hops (ตรวจ SSRF ทุก hop — ปิด auto-redirect แล้ววนเอง)
   - **prebuffer:** สะสม bytes แรกจนครบ 2–5 s โดยประมาณ (ใช้ threshold bytes ~256 KB หรือครบเงื่อนไขเวลา) แล้วค่อยตอบ
   - ตอบ: 206 + `Content-Range`/`Accept-Ranges: bytes`/`Content-Length`/`Content-Type` passthrough (หรือ 200 เมื่อไม่มี Range)
   - stall > 30 s → abort + ล้าง upstream
4. Error mapping: resolver ล่ม/timeout → 503 UPSTREAM_UNAVAILABLE; track เป็น local/isStream=false source ไม่รู้จัก → 422 TRACK_UNPLAYABLE
