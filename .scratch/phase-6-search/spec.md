## Scope

- Search รวมผล **local library** (pg_trgm GIN บน title/artist — index มีอยู่แล้วใน
  migration 0000) + Lavalink (ytsearch/ytmsearch — มีตั้งแต่ Phase 2) แล้ว dedupe
  ตาม track id (search ทุกครั้ง upsert ลง tracks อยู่แล้ว → library/remote id เดียวกัน)
- **Fail-soft ตาม backend.md §2 SearchService:** Lavalink ล่ม → ตอบผล library ที่มี +
  degraded:[source] (เปลี่ยนจาก Phase 2 ที่ 503 ทันที); library ก็ว่างด้วย → ค่อย 503
- **Auth บน /search** (requireAuth — api.md §3 rate limit "30/นาที/user" ระบุ per-user;
  web ส่ง Bearer อยู่แล้ว) + searchGuard 30 req/min/user (in-memory window เดียวกับ
  pattern streamGuard)
- **Pagination:** `?offset=` — Lavalink /loadtracks คืนชุดเดียว (~20 ผล) ไม่รองรับ
  deep offset จริง → ตัด slice จากชุดที่ได้, UI ซ่อนปุ่มเมื่อไม่มีหน้าถัดไป (ตัดสินใจ
  บันทึกใน spec — deep pagination ทำไม่ได้จนกว่าจะใช้ YouTube Data API)
- **Tracks endpoints (api.md §3):** GET /tracks/:id → TrackDTO (404), GET /tracks?ids=
  (≤ 50, dedupe ids) → { tracks }
- **Frontend:** useSearch (debounce 300 ms + TanStack Query cache/staleTime 60 s) —
  ค้นขณะพิมพ์, ปุ่ม "โหลดเพลงเพิ่มเติม", badge เมื่อ source degraded, Track detail page
  (/track/:id) พร้อมปุ่ม play/add-to-queue
